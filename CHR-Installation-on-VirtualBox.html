১ ওভারভিউ ও স্কোপ

▼

MikroTik CHR (Cloud Hosted Router) হলো RouterOS-এর একটি ভার্চুয়ালাইজড সংস্করণ, যা আপনি VirtualBox-এর মতো হাইপারভাইজারে চালাতে পারেন। এটি ফিজিক্যাল MikroTik রাউটার কেনার আগে RouterOS শেখার, ল্যাব তৈরি করার, অথবা প্রোডাকশনে ভার্চুয়াল রাউটার হিসেবে ব্যবহার করার জন্য আদর্শ।

স্কোপ (Scope)

  • অন্তর্ভুক্ত: VirtualBox-এ CHR VDI ইমেজ ইমপোর্ট, VM কনফিগারেশন, প্রথম বুট, প্রাথমিক নেটওয়ার্কিং, লাইসেন্সিং, ভেরিফিকেশন, Troubleshooting এবং প্রোডাকশন বেস্ট প্র্যাকটিস।
  • বাদ: VMware/Hyper-V/KVM-এ ইনস্টলেশন (আলাদা টপিক), জটিল রাউটিং প্রোটোকল কনফিগারেশন (BGP/OSPF), এবং ফিজিক্যাল MikroTik হার্ডওয়্যার।
  • ভার্সন: RouterOS v7.x (CHR)। v6-এর সাথে গুরুত্বপূর্ণ পার্থক্য থাকলে উল্লেখ করা হবে।

কেন VirtualBox-এ CHR?

  • ফ্রি এবং ক্রস-প্ল্যাটফর্ম (Windows, macOS, Linux)।
  • দ্রুত সেটআপ, সহজ স্ন্যাপশট ও রোলব্যাক।
  • প্রোডাকশন রাউটার কনফিগারেশনের নিরাপদ অনুশীলন।
  • ফ্রি লাইসেন্সে ১ Mbps থ্রুপুট — শেখার জন্য যথেষ্ট।
ℹ️ তথ্য CHR-এর ফ্রি লাইসেন্সে প্রতি ইন্টারফেসে ১ Mbps আপলোড সীমা আছে। ল্যাব ও শেখার জন্য এটি যথেষ্ট, কিন্তু থ্রুপুট টেস্টিং বা প্রোডাকশন ব্যবহারের জন্য পেইড লাইসেন্স বা ৬০ দিনের ট্রায়াল প্রয়োজন। [citation:5][citation:6]

২ পাঁচটি প্রধান স্তম্ভ (Five Priority Pillars)

▼

এই হ্যান্ডবুকের পাঁচটি মূল স্তম্ভ হলো:

  1. ধারণা ও কনফিগারেশন: CHR কী, কেন VirtualBox, এবং ধাপে ধাপে কনফিগারেশন।
  2. ভেন্ডর-স্পেসিফিক কমান্ড: MikroTik RouterOS v7-এর সঠিক CLI কমান্ড।
  3. হ্যান্ডস-অন ল্যাব: বাস্তব টপোলজি, কনফিগারেশন এবং টেস্ট।
  4. ভেরিফিকেশন ও Troubleshooting: প্রতিটি ধাপ যাচাই এবং সমস্যা সমাধান।
  5. বেস্ট প্র্যাকটিস ও সতর্কতা: প্রোডাকশন ব্যবহারের নিরাপদ নির্দেশিকা।

নিচের সেকশনগুলোতে এই পাঁচটি স্তম্ভকে সবচেয়ে বেশি গভীরতা দিয়ে আলোচনা করা হয়েছে।

৪ আর্কিটেকচার ও টপোলজি

▼

VirtualBox-এ CHR-এর সাধারণ টপোলজি

Host OS → VirtualBox → CHR VM

Network Modes:
NAT (Internet access for CHR)
Bridged (CHR on physical LAN)
Host-Only (Host ↔ CHR management)
Internal (CHR ↔ other VMs)

কম্পোনেন্ট

  • Host: আপনার ফিজিক্যাল কম্পিউটার (Windows/macOS/Linux)।
  • Hypervisor: VirtualBox — ভার্চুয়াল মেশিন চালায়।
  • Guest (CHR): RouterOS চালানো ভার্চুয়াল রাউটার।
  • Virtual Disk (VDI): CHR-এর বুট ডিস্ক।
  • Virtual NIC: VirtualBox-এর ভার্চুয়াল নেটওয়ার্ক অ্যাডাপ্টার।

৫ ELI10 ও ELI15

▼

ELI10 (সহজ উপমা)

ভাবুন, আপনার কম্পিউটার হলো একটি বড় বাড়ি। VirtualBox হলো সেই বাড়ির ভেতরে একটি ছোট ঘর। CHR হলো সেই ঘরে রাখা একটি ছোট রাউটার — যা দেখতে ভার্চুয়াল, কিন্তু কাজ করে আসল রাউটারের মতোই। আপনি এতে ক্লিক করে, কমান্ড দিয়ে নেটওয়ার্ক শিখতে পারেন, কোনো আসল রাউটার কেনার দরকার নেই।

ELI15 (প্রযুক্তিগত)

CHR হলো RouterOS-এর একটি x86-64 ভার্চুয়াল ইমেজ। VirtualBox একটি Type-2 হাইপারভাইজার যা হোস্ট OS-এর উপর চলে। CHR VM বুট হলে VirtualBox-এর ভার্চুয়াল NIC-গুলো RouterOS ইন্টারফেস হিসেবে দেখা যায় (যেমন ether1, ether2)। আপনি NAT/Bridged/Host-Only মোডে নেটওয়ার্কিং কনফিগার করতে পারেন। ম্যানেজমেন্ট WinBox (TCP 8291), SSH (TCP 22), বা WebFig (HTTP/HTTPS) দিয়ে করা যায়।

৭ কেন ও কীভাবে (WHY & HOW)

▼

কেন CHR?

  • ফিজিক্যাল রাউটার কেনার আগে RouterOS শেখা।
  • ল্যাব টেস্টিং — কনফিগারেশন ভাঙা ও ঠিক করার নিরাপদ পরিবেশ।
  • ছোট প্রোডাকশন ভার্চুয়াল রাউটার (লাইসেন্সসহ)।
  • ক্লাউড/ভার্চুয়ালাইজড পরিবেশে রাউটিং।

কীভাবে কাজ করে?

  1. CHR VDI ইমেজ VirtualBox-এ অ্যাটাচ করা হয়।
  2. VM বুট হলে RouterOS কার্নেল লোড হয়।
  3. VirtualBox-এর ভার্চুয়াল NIC-গুলো RouterOS-এ ether ইন্টারফেস হিসেবে দেখা যায়।
  4. RouterOS তার নিজস্ব IP স্ট্যাক, ফায়ারওয়াল, রাউটিং টেবিল ব্যবহার করে।
  5. ম্যানেজমেন্ট WinBox/SSH/WebFig দিয়ে করা হয়।

৮ পূর্বশর্ত (Prerequisites)

▼

হার্ডওয়্যার

  • 64-bit প্রসেসর, VT-x/AMD-V ভার্চুয়ালাইজেশন সাপোর্ট (BIOS-এ চালু)।
  • ন্যূনতম ২৫৬ MB RAM CHR-এর জন্য; ১০২৪ MB প্রস্তাবিত।
  • CHR VDI ইমেজের জন্য ডিস্ক স্পেস (~১২৮ MB)।

সফটওয়্যার

  • VirtualBox-এর সর্বশেষ সংস্করণ (অফিসিয়াল সাইট থেকে)।
  • MikroTik CHR VDI ইমেজ (mikrotik.com/download থেকে)।
  • WinBox (ঐচ্ছিক, কিন্তু সুপারিশকৃত)।

নেটওয়ার্ক

  • NAT মোডে ইন্টারনেট অ্যাক্সেস (ডিফল্ট)।
  • Bridged মোডে ফিজিক্যাল নেটওয়ার্কের সাথে সংযোগ।
  • Host-Only মোডে হোস্ট থেকে ম্যানেজমেন্ট।

১১ বেসিক কনফিগারেশন (VirtualBox-এ CHR ইনস্টল)

ধাপ ১: CHR VDI ডাউনলোড

MikroTik-এর অফিসিয়াল ডাউনলোড পেজ থেকে Cloud Hosted Router সেকশনে যান এবং VirtualBox (VDI) ইমেজ ডাউনলোড করুন। Stable সংস্করণ প্রোডাকশনের জন্য প্রস্তাবিত। [citation:1][citation:12]

ধাপ ২: VirtualBox-এ নতুন VM তৈরি

VirtualBox GUI — New VM

Memory:  1024 MB (ন্যূনতম 256 MB)
CPU:     1-2 (ওয়ার্কলোড অনুযায়ী)
Disk:    "Use an existing virtual hard disk file" → CHR.vdi নির্বাচন করুন

ধাপ ৩: VM সেটিংস

  • System → Boot Order: Hard Disk প্রথমে, Floppy/Optical আনচেক করুন। [citation:1]
  • Network → Adapter 1: NAT অথবা Bridged নির্বাচন করুন। [citation:1]
  • Audio/USB: প্রয়োজন না হলে ডিজেবল করুন।

উদ্দেশ্য

  4. Network → Adapter 1 → NAT।
  5. VM চালু করুন, admin/blank দিয়ে লগইন করুন।
  6. /interface print দিয়ে ether1 দেখুন।
  7. /ip dhcp-client add interface=ether1 disabled=no
  8. /ip address print দিয়ে IP যাচাই করুন।
  9. /ping 8.8.8.8 দিয়ে ইন্টারনেট টেস্ট করুন।

সফলতার মাপকাঠি

ক্লিনআপ

VM বন্ধ করুন এবং VirtualBox থেকে মুছে ফেলুন অথবা স্ন্যাপশট নিন।

২৭ ইন্টারমিডিয়েট ল্যাব

▼

Intermediate

উদ্দেশ্য

দুটি নেটওয়ার্ক অ্যাডাপ্টার (NAT + Host-Only) কনফিগার করে WinBox অ্যাক্সেস নিশ্চিত করা।

টপোলজি

Host (192.168.56.1) ← Host-Only → CHR ether2 (192.168.56.2)

CHR ether1 (NAT 10.0.2.15) → Internet

ধাপ

  1. VirtualBox → Settings → Network → Adapter 2 → Host-Only।
  2. CHR-এ /ip address add address=192.168.56.2/24 interface=ether2।
  3. হোস্ট থেকে WinBox চালু করে 192.168.56.2-এ সংযোগ করুন।
  4. ডিফল্ট admin পাসওয়ার্ড পরিবর্তন করুন।
  5. ফায়ারওয়াল রুল যোগ করে ether1 থেকে WinBox ব্লক করুন।

সফলতার মাপকাঠি

২৮ অ্যাডভান্সড ল্যাব

▼

Advanced

উদ্দেশ্য

CHR-কে DHCP সার্ভার হিসেবে কনফিগার করে Internal নেটওয়ার্কে অন্য VM-কে IP দেওয়া।

টপোলজি

CHR ether3 (10.10.10.1/24) → Internal Network → Client VM (DHCP)

ধাপ

  1. VirtualBox-এ Adapter 3 → Internal Network (নাম: "labnet")।
  2. CHR-এ: /ip address add address=10.10.10.1/24 interface=ether3
  3. /ip pool add name=lab-pool ranges=10.10.10.100-10.10.10.200
  4. /ip dhcp-server add interface=ether3 address-pool=lab-pool disabled=no
  5. /ip dhcp-server network add address=10.10.10.0/24 gateway=10.10.10.1
  6. Client VM বুট করে DHCP থেকে IP পেয়েছে কিনা দেখুন।

চ্যালেঞ্জ

ক্লায়েন্ট VM থেকে ইন্টারনেট অ্যাক্সেস নিশ্চিত করতে CHR-এ NAT (masquerade) কনফিগার করুন।

২৯ ইন্টারভিউ প্রশ্ন

▼

বিগিনার

প্রশ্ন ১: CHR কী?
উত্তর: Cloud Hosted Router — RouterOS-এর ভার্চুয়াল সংস্করণ।

প্রশ্ন ২: CHR-এর ডিফল্ট লগইন কী?
উত্তর: admin, পাসওয়ার্ড খালি।

প্রশ্ন ৩: VirtualBox-এ CHR-এর জন্য কোন ডিস্ক ফরম্যাট?
উত্তর: VDI (VirtualBox Disk Image)।

ইন্টারমিডিয়েট

প্রশ্ন ৪: NAT এবং Bridged মোডের পার্থক্য?
উত্তর: NAT-এ VM হোস্টের মাধ্যমে ইন্টারনেট পায়, বাইরে থেকে অ্যাক্সেসযোগ্য নয়। Bridged-এ VM ফিজিক্যাল নেটওয়ার্কে সরাসরি দেখা যায়।

প্রশ্ন ৫: ফ্রি লাইসেন্সের থ্রুপুট সীমা কত?
উত্তর: ১ Mbps প্রতি ইন্টারফেস।

প্রশ্ন ৬: ট্রায়াল লাইসেন্স কীভাবে চালু করবেন?
উত্তর: /system/license/renew account=... password=... level=p1

অ্যাডভান্সড

প্রশ্ন ৭: একই VDI থেকে একাধিক VM বানালে লাইসেন্স সমস্যা কেন হয়?
উত্তর: System ID একই থাকে। /system/license/generate-new-id দিয়ে নতুন ID তৈরি করতে হয় (শুধু ফ্রি লাইসেন্সে)।

প্রশ্ন ৮: ট্রায়াল মেয়াদ শেষ হলে কী হয়?
উত্তর: CHR চলতে থাকে কিন্তু ১ Mbps-এ ফিরে যায় এবং RouterOS আপগ্রেড করা যায় না।

৩০ চ্যালেঞ্জ

▼

পরিস্থিতি: আপনাকে একটি VirtualBox হোস্টে CHR কনফিগার করতে বলা হলো যেখানে:

  • ether1 = NAT (ইন্টারনেট)
  • ether2 = Host-Only (ম্যানেজমেন্ট, 192.168.56.0/24)
  • ether3 = Internal (ল্যাব নেটওয়ার্ক, 10.10.10.0/24, DHCP সার্ভার)

শর্ত: WinBox শুধুমাত্র Host-Only থেকে অ্যাক্সেসযোগ্য হবে। Internal নেটওয়ার্কের ক্লায়েন্টরা NAT-এর মাধ্যমে ইন্টারনেট পাবে। admin পাসওয়ার্ড অবশ্যই পরিবর্তন করতে হবে।

💡 হিন্ট ১

NAT-এর জন্য /ip firewall nat add chain=srcnat out-interface=ether1 action=masquerade

💡 হিন্ট ২

WinBox সীমিত করতে /ip service set winbox address=192.168.56.0/24

💡 হিন্ট ৩

DHCP সার্ভার ether3-এ দিন, pool 10.10.10.100-200, gateway 10.10.10.1
